# 2차 확장 구현 결정

기준: `A02_설계_문서_최종본.md`(2026-11-19)와 `2차_기획서_원판_A02팀.pdf`(73쪽). 원본 문서는 변경하지 않았습니다. PDF에는 기존 문구와 개정 문구가 함께 추출되는 부분이 있습니다. 새 기능을 삭제하면 여러 절을 다시 작성해야 하므로, 개정된 데이터 정의·세부 메뉴·7.7절 검수 사례와 설계 문서가 일치하는 해석을 선택했습니다. 아래 표는 원본을 정리할 때 필요한 최소 수정 지점입니다.

| 모순 또는 중복 | 구현과 최소 문서 정리 | 근거 |
| --- | --- | --- |
| 두 파일/세 파일, 논리 4/5필드, 물리 3/6필드 병기 | 세 파일, 5/6필드로 확정. 이전 스키마를 설명한 문구만 삭제 | 기획서 4.9~4.11, 5.2~5.3.1, 설계 3절 |
| 판매여부 boolean과 상태 0/1/2 혼재 | 상태로 저장. 재고는 H−T−D, 창고는 상태 0만 합산 | 기획서 4.6, 설계 2절 |
| FIFO 위반 오류 문구와 임박순·직접 지정·환불의 충돌 | 접미번호별 판매 상태 제약 제거. 기존 FIFO 오류 항목 삭제 | 기획서 5.4.3, 6.3, 7.7(70쪽), 설계 3절 |
| 가격 입력 후 등록 완료와 유통기한 입력 후 완료 중복 | 마지막 유통기한 입력 후 한 번 등록. 6.1.3의 완료 부분만 삭제 | 기획서 6.1.4, 설계 5.1 |
| 수량 입력 직후 입고 완료와 생산일 입력 단계 중복 | 수량·생산일 검증 후 한 번 저장. 이전 완료 문구 삭제 | 기획서 6.2.3~6.2.4, 설계 5.1 |
| 주 메뉴 1~5 설명과 환불 6·날짜 변경 7 추가 | 1~7 허용, 종료는 5 유지. 이전 메뉴 범위만 수정 | 기획서 6, 6.8~6.9, 설계 5.5 |
| 날짜 파일은 한 행이라는 표현과 최초 빈 파일 허용 | 최초 미설정은 0바이트 허용. 물리 기록이 있으면 날짜 필수 | 기획서 5.3.1, 5.4.5, 6.9.1, 설계 3절 |
| 폐기는 만료 후에만 생긴다는 설명과 날짜 저장 일부 실패 | 유기한 상태 2의 미래 만료일도 허용. 상태 0으로 자동 복구하지 않음 | 기획서 7.4, 7.7 마지막 보완 사례, 설계 5.4 |

만료일은 생산일+유통기한 일수이고 당일까지 유효합니다. 환불은 판매일 차이 0~14일, 만료 여부, 최초 환불 여부, 공간 순으로 검사합니다. 재판매 할인은 낱개별 `max(10, (정가*70L/1000)*10)`을 합산합니다. 판매 수는 거래 횟수가 아니라 현재 상태 1의 개수입니다.

서비스 오류 상세값은 설계대로 문자열 맵을 사용합니다. 저장 실패는 종료 코드 1이며 날짜 변경은 물리 파일, 날짜 파일 순으로 저장합니다. 날짜 메모리 값은 날짜 파일 닫기가 성공한 뒤 갱신합니다. 검증 실패 시 데이터는 변경하지 않고, 저장 실패 시에는 일부 파일·메모리 변경이 남을 수 있습니다.

기존 미커밋 `InputPatterns.java`, `docs/`, `scripts/`, `src/test/` 자료를 유지했습니다. 기존 서비스 검수 테스트는 확장된 메서드 인자와 최초 날짜 조건만 반영했습니다. 1차 전용 Python 검수 스크립트는 그대로 보존했으며, 2차 실행 검증은 `scripts/review_phase2.py`, 저장 실패와 업무 경계는 `Phase2ServiceTest`가 담당합니다. 실제 `data/` 파일은 수정하지 않았습니다.
